# 실험 사용법 가이드 (처음부터 끝까지) — **Ubuntu**

이 문서는 **우분투(Ubuntu) Linux**에서 **설치부터 실험 실행까지** 순서대로만 따라 하면 되도록 적었습니다.  
어려운 단어는 괄호 안에 쉬운 말을 붙였습니다.

> 다른 OS(Windows 등)는 이 문서와 패키지 설치 방법이 다릅니다.

---

## 이 프로젝트가 하는 일 (한 줄 요약)

여러 개의 작은 프로그램(마이크로서비스)이 **줄을 지어** 요청을 전달합니다.

**순서:** 입구(Gateway) → 주문(Order) → 재고(Inventory) → 사용자(User)

실험에서는 이 줄을 **부하 테스트**(많은 요청 보내기)하거나, **JWT 모드**로 바꿔서 로그인 토큰이 필요한지 비교할 수 있습니다.

---

## 0단계. 미리 준비할 것 (도구 설치, Ubuntu)

아래는 **한 번만** 설치하면 됩니다. 터미널은 **Ctrl + Alt + T** 로 열 수 있습니다.  
`sudo`가 나오면 **관리자 비밀번호**를 물을 수 있습니다.

### 0-0. 패키지 목록 갱신 (처음 한 번)

```bash
sudo apt update
```

### 0-1. 자바(JDK 17)

```bash
sudo apt install -y openjdk-17-jdk
java -version
```

화면에 `17`이라는 숫자가 보이면 성공입니다. (예: `openjdk version "17.0.x"`)

### 0-2. Maven (빌드 도구)

```bash
sudo apt install -y maven
mvn -version
```

버전 정보가 나오면 성공입니다.

### 0-3. Docker (컨테이너 실행) + Compose

실험은 **Docker Compose**로 돌립니다. Ubuntu에서는 보통 **Docker Engine**을 씁니다. (Windows용 Docker Desktop과는 별개입니다.)

**방법 A — Ubuntu 저장소로 간단히 설치 (실습용으로 흔함)**

```bash
sudo apt install -y docker.io docker-compose-v2
```

`docker compose` 명령이 없다면 다음도 시도합니다.

```bash
sudo apt install -y docker.io docker-compose-plugin
```

**방법 B — 공식 문서대로 최신 Docker CE 설치**  
(학교·랩에서 정한 절차가 있으면 그쪽을 따릅니다.)

설치 후:

```bash
sudo systemctl enable --now docker
sudo systemctl status docker
```

`active (running)` 이 보이면 데몬이 떠 있는 상태입니다.

**현재 사용자에게 Docker 쓰기 권한 주기** (매번 `sudo` 없이 쓰려면):

```bash
sudo usermod -aG docker "$USER"
```

적용하려면 **로그아웃 후 다시 로그인**하거나, 한 세션만:

```bash
newgrp docker
```

확인:

```bash
docker version
docker compose version
```

오류 없이 나오면 성공입니다.

### 0-4. Git (코드 받기)

```bash
sudo apt install -y git
git --version
```

### 0-5. (선택) JMeter (부하 테스트 GUI 또는 CLI)

```bash
sudo apt install -y jmeter
jmeter --version
```

GUI가 없는 서버에만 SSH로 붙어 있다면, JMeter는 **자기 노트북(우분투)** 에 설치하고 같은 네트워크의 Gateway 주소로 `HOST`만 바꿔도 됩니다.

### 0-6. (선택) 브라우저에서 주소만 열고 싶을 때

데스크톱 우분투면 크롬·파이어폭스 등 아무거나 사용합니다.  
서버만 있고 화면이 없으면 **7단계의 curl**로 확인하면 됩니다.

## 1단계. 프로젝트 폴더 준비

### 1-1. 코드를 받는다

1. 실험할 폴더를 정한다. (예: 홈 아래 `~/school/MSA-Auth-Performance-Benchmark`)
2. 터미널을 연다.
3. Git으로 이미 받았다면 그 폴더로 이동한다.

```bash
cd ~/school/MSA-Auth-Performance-Benchmark
```

4. 아래로 파일이 보이면 올바른 위치입니다.

```bash
ls pom.xml docker-compose.yml
```

### 1-2. 환경 변수 파일 `.env` (Docker Compose용, 권장)

`docker-compose.yml` 은 `${APP_MODE}`, `${JWT_SECRET}` 같은 값을 **쉘 환경 변수** 또는 **프로젝트 루트의 `.env` 파일**에서 가져옵니다.  
비밀값은 Git에 올리지 않도록 **`.env.example`** 만 저장소에 있고, **`.env`** 는 `.gitignore` 로 제외됩니다.

처음 한 번:

```bash
cp .env.example .env
```

필요하면 편집한다. (예: `APP_MODE=jwt-relay`, `JWT_SECRET` 변경)

> **참고:** `mvn` 으로 로컬 실행만 할 때는 Spring Boot가 `.env` 를 자동으로 읽지 **않습니다**. 그때는 터미널에서 `export APP_MODE=...` 하거나 IDE 실행 설정에 넣습니다.

## 2단계. 프로그램 빌드하기 (Maven)

**빌드**란: 소스 코드를 실행 가능한 파일로 만드는 작업입니다.

### 2-1. 프로젝트 루트에서 실행

1. 터미널에서 **프로젝트 루트**에 있는지 확인한다. (`pom.xml`이 있는 폴더)
2. 아래를 실행한다.

```bash
mvn -DskipTests package
```

3. 처음에는 시간이 걸릴 수 있다. 마지막에 `BUILD SUCCESS` 비슷한 글이 나오면 성공이다.
4. 실패하면 JDK 17인지 다시 확인한다.

### 2-2. JWT 만들기 도구만 따로 빌드하고 싶을 때

```bash
mvn -pl benchmark-tools -am -DskipTests package
```

성공하면 `benchmark-tools/target/` 아래에 `benchmark-tools-1.0.0-SNAPSHOT-exec.jar` 같은 파일이 생긴다. (버전 숫자는 바뀔 수 있음)

## 3단계. Docker로 전체 서비스 실행하기 (가장 쉬운 방법)

**Docker Compose**는 여러 컨테이너를 한 번에 켜 주는 설정 파일(`docker-compose.yml`)이다.

### 3-1. Docker 데몬이 돌아가는지 확인

```bash
sudo systemctl status docker
```

`active (running)` 이 아니면:

```bash
sudo systemctl start docker
```

### 3-2. 프로젝트 루트에서 실행

```bash
cd ~/school/MSA-Auth-Performance-Benchmark
docker compose up --build
```

- `permission denied` 가 나오면 0-3의 **docker 그룹** 설정을 하고 로그아웃·로그인했는지 확인한다.

처음에는 이미지를 만드느라 오래 걸릴 수 있다. 로그가 계속 올라오면 정상이다. **그대로 둔다** (서버가 켜진 상태).

### 3-3. 잘 켜졌는지 확인하는 방법

**새 터미널 탭**을 연다. (기존 창은 닫지 않는다.)

**방법 1 — 브라우저 (데스크톱 우분투)**

주소창에:

```text
http://localhost:8080/api/chain
```

**방법 2 — 터미널만 있을 때**

```bash
curl -sS http://localhost:8080/api/chain | head -c 500
```

JSON 형태의 글이 보이면 **성공**이다. `gateway`, `order`, `user` 같은 단어가 섞여 있으면 정상 응답이다.

### 3-4. Jaeger (추적 화면) 열기

브라우저에서:

```text
http://localhost:16686
```

## 4단계. 실험 모드 이해하기 (중요)

환경 변수 **`APP_MODE`** 두 가지를 기억한다.

| 값 | 쉬운 말 | 언제 쓰나 |
|----|---------|-----------|
| `no-auth` | 앱 안에서는 로그인 검사 안 함 | 베이스라인, 사이드카만, mTLS만(Istio가 알아서 할 때) |
| `jwt-relay` | JWT 토큰을 검사하고 다음 서비스로 전달 | JWT 실험(Step 1) |

기본값은 **`no-auth`** 이다. (`docker-compose.yml`에 그렇게 되어 있음)

---

## 5단계. JWT 모드로 바꿔서 실행하기

### 5-1. 실행 중인 Docker를 먼저 끈다

`docker compose up`을 켜 둔 터미널에서 **Ctrl + C**를 누른다.

### 5-2. Ubuntu 터미널에서 환경 변수를 설정하고 다시 켠다

**한 줄로** (같은 터미널에서 곧바로 실행):

```bash
export APP_MODE=jwt-relay
docker compose up --build
```

**설명:** `export`는 **지금 연 터미널 창 안에서만** 유효하다. 창을 닫으면 사라진다.

### 5-3. JWT 없이 브라우저로 접속하면?

`http://localhost:8080/api/chain` 에 접속했을 때 **401** 같은 오류가 나올 수 있다.  
이건 **정상**이다. (이제 토큰이 필요하다는 뜻)

---

## 6단계. JWT 토큰 만들기

### 6-1. 토큰 생성 프로그램 실행

**새 터미널**을 연다. (Docker는 계속 켜 둔다.)

프로젝트 루트에서 (이미 2단계에서 빌드했다고 가정):

```bash
cd ~/school/MSA-Auth-Performance-Benchmark
java -jar benchmark-tools/target/benchmark-tools-1.0.0-SNAPSHOT-exec.jar \
  --secret "benchmark-jwt-hmac-secret-key-min-32-bytes!!"
```

- 파일 이름의 버전이 다르면:

```bash
ls benchmark-tools/target/*-exec.jar
```

에 나온 이름을 그대로 쓴다.

화면에 **아주 긴 한 줄**이 나온다. 이게 **JWT 토큰**이다. 변수에 넣어 두면 편하다.

```bash
TOKEN="$(java -jar benchmark-tools/target/benchmark-tools-1.0.0-SNAPSHOT-exec.jar --secret "benchmark-jwt-hmac-secret-key-min-32-bytes!!")"
echo "$TOKEN"
```

### 6-2. 비밀번호(secret)를 바꾼 경우

Docker와 **똑같은** `JWT_SECRET`으로 토큰을 만들어야 한다.

---

## 7단계. JWT가 있을 때 요청 보내기

### 방법 A: curl (우분투에 기본 포함)

`TOKEN`을 6단계 문자열로 바꿔 넣는다.

```bash
curl -sS -H "Authorization: Bearer TOKEN여기에붙여넣기" http://localhost:8080/api/chain
```

`$TOKEN` 변수를 썼다면:

```bash
curl -sS -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/chain
```

JSON이 나오면 성공이다.

### 방법 B: Postman, 브라우저 확장 등

주소: `http://localhost:8080/api/chain`  
헤더: `Authorization` = `Bearer (토큰)`

## 8단계. JMeter로 부하 테스트하기

### 8-1. 파일 위치

프로젝트의 `jmeter/` 폴더.

- `msa-chain-no-auth.jmx` → **no-auth** 모드
- `msa-chain-jwt.jmx` → **jwt-relay** 모드

### 8-2. GUI로 여는 방법

```bash
jmeter &
```

**File → Open**으로 `jmeter/msa-chain-no-auth.jmx` 등을 연다.  
**User Defined Variables**에서 `HOST`, `PORT`, (JWT일 때) `JWT_TOKEN`을 설정한다.

### 8-3. 명령줄만으로 돌리기 (비 GUI)

프로젝트 루트에서:

```bash
mkdir -p results
jmeter -n -t jmeter/msa-chain-no-auth.jmx -l results/no-auth.jtl
```

JWT 모드 (토큰을 한 줄로 붙임):

```bash
jmeter -n -t jmeter/msa-chain-jwt.jmx -JJWT_TOKEN=여기에토큰한줄 -l results/jwt.jtl
```

### 8-4. JMX 기본값 (참고)

- 스레드 10, 램프업 30초, 스케줄 300초 등 — JMeter GUI에서 논문 조건에 맞게 수정 가능.

## 9단계. 실험할 때 권장 순서 (논문 Step과 연결)

1. Docker 데몬이 떠 있는지 확인 (`sudo systemctl status docker`).
2. **Step 0 / 2 / 3** — `APP_MODE` 없이 또는 `no-auth`로 `docker compose up --build` → `/api/chain` 확인 → `msa-chain-no-auth.jmx`.
3. **Step 1** — 컨테이너 중지 후 `export APP_MODE=jwt-relay` 하고 다시 올리기 → 토큰 생성 → `msa-chain-jwt.jmx` 또는 curl.
4. **Jaeger** — `http://localhost:16686`.

(Istio·mTLS·사이드카는 **Kubernetes + Istio** 환경에서 따로 설정. `k8s/` 참고.)

---

## 10단계. 모두 끄기

1. `docker compose up` 중인 터미널에서 **Ctrl + C**
2. 필요 없으면 Docker도 멈출 수 있음: `sudo systemctl stop docker` (다른 컨테이너도 같이 영향받을 수 있어 주의)

## 11단계. 잘 안 될 때 (Ubuntu에서 자주 나오는 것)

### `permission denied` (Docker)

```bash
sudo usermod -aG docker "$USER"
```

로그아웃 후 다시 로그인하거나 `newgrp docker`.

### 포트가 이미 쓰인다 (8080 등)

```bash
sudo ss -tlnp | grep 8080
```

다른 프로세스를 끄거나 `docker-compose.yml`의 포트를 바꾼다.

### `mvn`이 없다

0-2를 다시 실행한다.

### Docker 데몬이 안 뜬다

```bash
sudo systemctl start docker
sudo journalctl -u docker -e
```

### 원격 서버(SSH)에만 있고 브라우저가 없다

- `curl http://서버IP:8080/api/chain` (방화벽에서 8080 허용 필요할 수 있음)
- 또는 **SSH 터널**:  
  `ssh -L 8080:localhost:8080 사용자@서버` 후 **내 PC 브라우저**에서 `http://localhost:8080/api/chain`

### JWT 모드에서 계속 401

- 모든 컨테이너가 **같은** `JWT_SECRET`인지
- `Authorization: Bearer ` 와 토큰 사이 형식
- 토큰 만료 (`--ttl-minutes`로 늘리기 가능)

## 한 페이지 요약 표

| 하고 싶은 일 | 하는 일 (Ubuntu) |
|--------------|------------------|
